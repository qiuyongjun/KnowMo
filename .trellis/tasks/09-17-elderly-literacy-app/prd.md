# 老年人识字辅助应用-适老化安卓原型

## Goal

面向识字较少老年人的安卓识字辅助应用。本次交付为**高保真交互式 UI 原型**：以**生活词组**为学习单元、**抖音式上下滑 feed** 为核心交互的识字学习体验。技术路线 Kotlin + Jetpack Compose，原型确认后再实施完整工程。

> **交付现状（2026-09-17 更新）**：原型已确认并于 **v2 冻结**（不再迭代）；工程版 `android-app/` 为当前**唯一交付线**，已迭代至 v3。本文档的验收标准、适老化约束与数据模型均以 `android-app/` 为准。

## 用户画像

- 60 岁以上，识字量少（不识字或仅识少量常用字），视力衰退、手部精细操作能力下降。
- 独自进城生活或子女不在身边，需要在超市、医院、公交、银行等场景看懂标识、完成基本事务。
- 可能从未用过智能机复杂功能，对多级菜单、手势操作有畏惧感；听力和语音接受度好于文字。刷短视频式上下滑是老年人已被市场教育的交互习惯。

## Requirements

### v2 交互范式（2026-09-17 评审修订）

> v1 的"底部 Tab + 分页导航 + 独立复习界面"方案废弃。v2 采用抖音式垂直 feed。

1. **核心交互：上下滑动的学习 feed**
   - 每屏一个学习卡片，上滑看下一个，snap 吸附保证不会停在半张卡。
   - 无底部导航、无多级菜单、无长按；单指任意位置上滑即可，学习区域最大化。

2. **顶部分区 Tab（参考抖音顶部 tab）**
   - 横向场景频道：推荐 / 超市买菜 / 公交地铁 / 医院 / 银行 / 政务办事 / 餐馆吃饭。
   - 点按切换频道，feed 内容随之整体替换；当前频道高亮 + 语音播报频道名。

3. **学习单元：生活词组，不是单字**
   - 以生活中真实出现的**组合**为单元（如"地铁站"一起学，不拆成地/铁/站三课）。
   - 每词条卡：大字词组 + 逐字拼音 + 生活用途说明 + 场景图标背景 + 自动朗读；点卡片任意处重听。
   - 每个字仍支持点按单独发音（字卡弹层保留，用于查单字细节）。

4. **新学 + 复习混排（无独立复习界面）**
   - feed 队列由记忆曲线规划：到期复习项与新学项穿插出现。
   - 复习卡有"🔁 复习"角标（标注距上次间隔）：先只出词组不出拼音释义 → 两个超大反馈按钮"😀 认识 / 😕 忘了" → 展开完整内容 → 上滑继续。
   - 认识 → 下次间隔拉长（1→3→7→15 天）；忘了 → 明天再来（简化 Leitner，原型内即时反馈演示）。
   - 队列末尾为"今日完成"卡：语音表扬 + 从头再看一遍。

5. **第一版功能边界（明确排除）**
   - 不做手写录入（老年人以"认字"为目标，不要求写）。
   - 不做拍照识字（列入后续扩展）。
   - **不做"我的生词本"**（2026-09-17 决策）：不认识/忘了的词由每日队列自己承担——「忘了」当天尾部重现一次、且 `days` 重置为 1（次日再考），不需要单独的收集列表。
   - **不做设置页**（2026-09-17 决策）：不提供字体大小/语速/提醒时间入口。语速固定默认值（0.85x，适老偏慢），字号跟随系统缩放。

### 适老化设计约束（硬性）

- 词组主字号 ≥ 48sp 等效；拼音、说明 ≥ 22sp。**不单独提供"更大字体"开关**（2026-09-17 决策取消设置页），字号跟随系统缩放（`fontScale` 由系统提供，app 不叠加自有倍率）。
- 对比度：正文/背景 ≥ 7:1（WCAG AAA）；复习反馈按钮高饱和（绿=认识 / 深红=忘了）。
- 触控目标 ≥ 64dp 等效；反馈按钮 ≥ 88dp 高。
- 导航层级 = 1 屏（feed 常驻）+ 1 个弹层（字卡详情）；不依赖长按、双击、边缘手势。
- 关键操作语音引导：卡片进入视口自动朗读；按钮点击朗读含义。
- 上下滑为唯一翻页手势，snap 吸附防止半张卡造成的困惑。

### v3 交互修订（2026-09-17 讨论收敛，工程实现迭代）

> ⚠️ **2026-09-17 第二轮修订（v4，见下节）推翻本节决策①（推荐频道无配额 → 每日 10 词）**；第 7 条毕业判定（days==15 封顶）**保留**，但达成路径改为 v4 的多轮连击（见 v4 第 5 条）；冲突条款以 v4 为准。

> v2 工程版（android-app）已实现静态队列 feed。v3 修订针对实机体验三大痛点：复习卡泄题、静态队列重头开始、进度条暴露队列边界。

1. **滑动即播（分卡型，不泄题）**
   - 新词卡：滑到停稳（滑动进行中不播，停稳后 ~200ms debounce）自动念"词 + 提示语"。
   - 复习卡：滑到只播"这个词，还记得它念什么吗？"，**不念读音**（保住考回忆）；按"认识/忘了"后才念词+提示。
   - 完成卡：播报今日战果。
2. **去掉"第 x/y 张"进度条**：队列边界对用户不可见，进度由完成卡和语音表达。
3. **每日队列调度（替代静态 REC_QUEUE）**
   - 当日首次打开生成当日队列：**到期复习词优先（先清债）+ 全部未学新词**，交错混排（约每 2 新词插 1 复习）+ 内部洗牌 → 不知道后面是什么。
   - **推荐频道不设每日新词配额**（2026-09-17 决策，正式关闭"368 词首日 368 张 = 缺陷"的待决项）：抖音式 feed 的契约就是"想刷多久刷多久"，配额反而制造"今天必须刷完 N 张"的压力和一个用户看不见的隐性终点。老人随时停、随时回来即可，进度由完成卡与语音自然表达，不由数量表达。
   - 「忘了」：days 重置 1（明天到期），且当天队列尾部自动重现一次（错词当天再见）。
   - 「认识」：1→3→7→15 天升级，到期日到了自然出现在未来队列。**每日最多升一级** —— 同一个词当天已升过级（`lastSeen == 今天`）时重复作答不再升级。否则「完成卡→从头再看一遍」清空展开态后，可在同一天把间隔刷到封顶，分区毕业就绕过了间隔阶梯。
   - `kind` 从静态数据字段改为运行时计算：首次见=新学，到期=复习，自由刷=温故。
4. **完成卡 + 自由刷**：当日队列刷完出完成卡（语音表扬+战果）；继续上滑进入自由刷——已学词池随机回炉、循环不重样，随时可停，无强迫。
5. **持久化与断点**（SharedPreferences+JSON，36 词量级不上 Room）：
   - 每词状态：间隔天数、上次学习日期/到期日。
   - 当日队列 + 断点位置 + 日期戳：当天内重启从断点续刷；隔天重新调度（队列本身是新的，自然不重头）。
6. **场景频道走同一调度器**，按场景过滤（该场景的到期复习+未学新词），体验与推荐频道一致；**跨频道共享同一份学习状态**（同一词在推荐和场景频道共享 TermState），但各自维护独立队列。
7. **分区毕业（只做分区级，不做词级；2026-09-17 修订为纯进度标记）**
   - **没有「每日/词级毕业」机制**：词一旦学过就永久按 1/3/7/15 循环，不退出池 —— 老人需要长期复现维持记忆。`days` 在 15 天封顶后每 15 天仍会回到队列，这是**有意的长期维持**，不是疏漏。
   - **分区毕业判定**：某分区**每个词都连续 3 次「认识」** → 该分区毕业。实现上不新增计数器：连续 3 次认识恰好把 `days` 推到封顶值（1→3→7→15），任何一次「忘了」都会打回 1，所以 `days == 15` 即等价于「连续三次认识」。
   - **毕业效果（2026-09-17 决策修订）**：①频道栏该分区加 **🎓** 标记、文字转绿（纯进度感展示）；②**毕业分区的词仍正常排入推荐频道队列，仍可复习** —— 毕业不改变队列范围，只把"这个场景学明白了"可视化出来；③场景频道与自由刷池同样不受影响（本来就含全部词）。
   - **为什么改为纯标记**：上一版让毕业分区退出推荐队列，产生两个副作用——全部毕业后推荐频道当日队列为空（首屏直接落完成卡并播"认识了 0 个"），且毕业词只能靠场景频道复习（自由刷不推进 `days`，等于脱离复习循环）。改为纯标记后，「长期维持记忆」与「学完一块的进度感」同时成立，也不再需要"推荐排除毕业分区"这条特例规则。
   - **生效时机**：徽章即时更新（不再区分当日/次日，因为它已不影响队列生成）。

### v3 验收标准

- [ ] 复习卡自动朗读不念读音；新词卡滑到停稳自动念；快速连滑无"闪播"杂音。
- [ ] 界面无"第 x/y 张"进度条。
- [ ] 隔天打开队列重新调度；当天内重启从断点继续；忘了的词当天尾部重现。
- [ ] 完成卡后继续滑出现自由刷卡（已学词随机），badge 显示"温故"。
- [ ] 「认识/忘了」反馈逻辑保留，间隔升级持久化，重启不丢。
- [ ] 分区毕业：某区每个词都连续 3 次认识后，频道栏出现 🎓；该区词**仍正常出现在推荐频道队列**（毕业只作进度标记，不影响复习范围）。
- [ ] 推荐频道无每日新词配额；队列刷完出完成卡，继续上滑进入自由刷，随时可停。

### v4 交互修订（2026-09-17 第二轮拍板，第三轮修订定稿）

> v4 引入「当日连击计数 + 移除」的队列模型。**第二轮曾拍板纯计数方案（废除间隔阶梯）；第三轮修订（同日）定为间隔 + 连击双层**——连击只管当日移出队列，跨天仍按 1→3→7→15 间隔调度。**推翻 v3 决策①（无配额 → 每日 10 词）**；毕业判定 days==15 保留。

1. **推荐频道每日 10 词（替代 v3 决策①"无配额"）**
   - 当日首次调度：**到期复核词优先（按到期日升序，先清债）+ 未学新词洗牌补足，共 10 个**；不足 10 个则全排，一个也没有（无到期且无新词）当天直接自由刷。当日冻结，重启不换词。
   - 复核词 = 往日认识过、按间隔到期的词——「往日认识、当日不认识」的复核场景由此产生。
   - 配额只作用于推荐频道；场景频道不另设配额（自主选择学习节奏，见第 4 条）。

2. **每词 3 次「认识」连击才移除（间隔 + 连击双层）**
   - QYJ 口径：**当天同一个词连续三次「认识」后才算移除；任意一次「不认识」，计数清零。**
   - 连击层（当日队列）：每词当日计数（0–3），「认识」+1、「不认识」清零；满 3 → 移出当日队列。
   - 间隔层（全局记录）：满 3 移除时升一级间隔（1→3→7→15，每日最多升一级闸门保留）；「忘了」→ days=1 + 往期记录更新 → **影响分区完成情况**（该分区退出完成状态）。未满 3 的作答**不写** TermState → 词保持到期状态，次日自然回池继续。
   - 词的生命周期：新词卡（教读，无按钮）→ 复习卡 ×3 次「认识」（可同日连续）→ 移除当日队列 + 升一级 → 3/7/15 天后到期再复核 → days==15 毕业。

3. **任务池与「完成今日任务」**
   - 当日任务池 = 每日 10 词（复核优先 + 新词补足）；当天未连击满 3 的词保持到期，次日自动回池继续（即"遗留词"，由间隔到期实现，无需单独的遗留列表）。
   - 队列从池中生成，作答后未移除的词排到队尾再次出现，移除的词不再出现。
   - **池全部移除后**才出完成卡，播报"今日任务完成"；继续上滑进入自由刷——不限制、已学习的词都会刷到，**自由刷作答同样生效**（认识累计连击 / 忘了清零降级，均受「每日最多升一级」闸门约束）。
   - 忘了的卡（含自由刷/场景复习中忘了）→ days=1，次日到期回到任务池，**重新连击三次才能移除**（只重置计数与间隔，不回退为未学词）。

4. **场景频道统一模型 + 自主复习**
   - 场景频道与推荐频道**同一套连击 + 间隔模型**，仅无每日 10 词配额；任务池 = 该场景到期词 + 未学新词，自然见底（无到期且无新词时池为空）。
   - 池空或全部移除后 → 完成卡，继续滑进入**自主复习**（该场景已学词循环出卡）。
   - 自主复习中「不认识」→ 计数清零 + days=1 → 该词次日回到任务池重新学习，分区完成徽章即时回退。

5. **分区完成（days==15，多轮连击）**
   - 判定：分区内**每个词 days==15**（间隔封顶）→ 频道栏 🎓 + 文字转绿。达成 = 多轮不同日的满 3 连击（1→3→7→15），而非一次移除即毕业。
   - 任何一处「忘了」都会让该词 days 打回 1 → 分区立即退出完成状态（可逆，同 v3 的可逆性设计）；毕业后每 15 天到期仍回池复核（长期维持，同 v3）。

6. **v4 验收标准**

- [ ] 推荐频道每日 10 词 = 到期复核优先 + 新词补足；当日重启不换词，未满 3 的词次日回池继续。
- [ ] 同一个词当日连续 3 次「认识」即移出当日队列并升一级间隔；中途一次「忘了」则清零重来、days=1。
- [ ] 任务池全部移除后才出完成卡；完成卡文案为"今日任务完成"。
- [ ] 完成卡之后自由刷：已学词（含已移除）随机出现，作答按钮可用且连击/降级照算（受每日升一级闸门约束）。
- [ ] 自由刷/场景复习中「忘了」→ 计数清零、days=1，该词次日回到任务池；分区完成徽章即时回退。
- [ ] 分区完成 = 分区内全部词 days==15；间隔阶梯（1→3→7→15）、到期判定、GRADUATED_DAYS 保留有效。
- [ ] 新词卡停稳自动教读（无按钮）后排到队尾转复习卡作答；断点恢复、隔天重建行为不变。

### 原型范围与边界

> **原型已冻结于 v2（2026-09-17 决策 C）。** `prototype/index.html` 保留为 v2 交互演示的历史版本——它仍是 36 词/7 频道、静态 `REC_QUEUE`、含"第 x/y 张"进度条、含设置页与生词本、复习卡朗读会把词念出来（泄题）。
> **以上与 v3 的不一致是已知且有意保留的**，不构成缺陷，也不再回修：v3 起工程实现以 `android-app/` 为唯一交付线，原型不再同步、不再作为工程基准。词库、调度逻辑与适老化指标一律以 `android-app/` 与本文档为准。

- 交付物：单文件 HTML 高保真交互原型，手机框内运行，浏览器直接体验（含真实语音朗读）。
- 不包含：真实数据库、真实记忆调度、真机工程代码（属于确认后的下一任务）。
- 演示数据结构与后续工程数据模型对应：Term（词条）、TermChar（单字）、ReviewState（复习状态）。
