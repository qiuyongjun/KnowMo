# 学习与抽卡逻辑优化建议（对标主流单词软件）

> 基线：R10 之后的实现（`StudyRepository.kt` + `AppRoot.kt`，提交 `0d5c4a2`）。
> 对标来源：FSRS/DSR（Anki 2023 年起的默认算法）、墨墨背单词 MM 算法与其**产品规则**、不背单词 / 扇贝 / 百词斩，以及老年人 & 记忆障碍的间隔提取实证。
> 数字来源：本目录 `learning-mechanism-review.md` 的模拟器（可复跑）＋本文新增推算（已逐条标注来源）。
> 性质：**只做建议，未改任何代码**。凡涉及调度语义的改动都必须回 Phase 1（改 `prd.md` / `design.md`）才能动。

---

## 0. 一句话结论

Mando 这台机器的骨架是**对的**（间隔阶梯 + 遗忘史 + 到期优先 + 池型自主练习），但有三处与主流做法**方向性偏离**。其中最严重的一处不是「效率不够」，而是：

> **一个每天只能做完一部分卡的老人，在这套机制里永远学不会任何词，而且每天的卡数永远降不下来。**

原因是「满 3 连击才升级」这条规则把升级锁死在**同一天内**完成，而 `DayState` 隔天整体作废。做不完 → 计数清零 → 永远到不了 3 → 永远不写 `TermState` → 词永远停在原到期状态 → 明天还是这么多卡。这是一个**闭环死锁**。

---

## 1. 主流现在怎么做

### 1.1 FSRS（Anki 默认，2023 起）—— 调度层的事实标准

DSR 三参数模型：**Difficulty（难度）／Stability（稳定性）／Retrievability（可提取性）**。

| 维度 | SM-2（1987，Anki 用了 20 年） | FSRS |
|---|---|---|
| 参数 | 3 个（一个 ease factor） | 21 个可训练权重 |
| 间隔 | 固定倍数递增（×2.5） | 由稳定性 + 目标回忆概率反推 |
| 难度 | 全局一个系数，会「ease hell」 | **每卡独立** |
| 目标 | 无 | **可设目标记忆率**（默认 90%） |
| 同日复习 | 不建模 | **显式建模**（短期记忆效应） |

实测（2,836 人 / 12 亿条复习日志）：**同等保留率下复习量少 25–35%**，积压恢复快 3–5 倍。

**可迁移点**：间隔的语义应该是「回忆概率降到目标线的那一刻」，不是固定阶梯。但 Mando 没有 ML 所需的数据量，所以只该搬**概念**，不该搬算法（见 §4）。
**Mando 已经对的地方**：`lapses` 就是 difficulty 的粗粒度版本（每词独立）✓。

### 1.2 墨墨背单词 —— **产品规则比算法更值得抄**

它的算法（MM / SSP-MMC）学术上很硬，但对 Mando 更有价值的是这几条**产品规则**：

1. **「当天第一次出现」的记忆反馈决定长期调度；同一天后续出现的反馈只影响当天顺序，不影响间隔。**
2. **学习量 = 复习 + 新学，是一个整体**。复习多则新学少，不设固定新学量——理由是「固定新学量会让复习量持续累加，之后每天没时间完成」。
3. **「熟知」= 永久不再复习**（一个明确的出口）。
4. 答「忘记」→ **当天还会出现两次，且极大概率次日再出现**。
5. 反馈分四档（认识 / 模糊 / 忘记 / 熟知）。

### 1.3 其他

- **不背单词**：「需要连续多次答对才算一次复习」——和 Mando 的 3 连击同源，说明这不是孤例，但它是**面向学生**的产品。
- **扇贝**：单词卡页提供**「更改为不认识」**按钮——明确的**纠错入口**。
- **百词斩**：「一词一图」的视觉锚定。

### 1.4 老年人 & 记忆障碍的实证（主线，但主流背单词软件不覆盖）

- **间隔提取（spaced retrieval）**：待记内容在**递增的间隔**上被反复测试，是记忆障碍 / 老年认知干预中证据最扎实的方法之一。错误要**立即纠正**；**出错时把间隔缩回上一档，再重新递增**（Haslam et al. 2011）。
- **错误最小化（errorless / error-reducing learning）**：学习阶段减少错误，对记忆受损者的效果优于允许试错。
- **Maddox & Balota（2015）的年龄差异结论（关键）**：
  > 「重复的**间隔**提取」对年轻人和老人都有效；
  > 「重复的**密集**提取」**只对年轻人有效**。
- 长期保留需要 **booster sessions**（后续加强场次）。

## 2. 差距清单

| # | 维度 | 主流做法 | Mando 现状 | 性质 |
|---|---|---|---|---|
| 1 | **升级判据** | 首答（当天第一次反馈）即定长期调度 | 当日**满 3 连击**才升级，且计数隔天作废 | ⚠️ **方向性偏离** |
| 2 | 误答纠错 | 扇贝有「更改为不认识」；FSRS 的 Again 只是降级 | 作答即写库，**无撤销窗口** | 缺口 |
| 3 | **队内顺序** | 新卡与复习卡交错或新卡前置 | `(due + news).take(10)` → **到期词全在前、新词垫底** | ⚠️ 方向性偏离 |
| 4 | 债务高峰 | 学习量整体守恒（复习多则新学少） | 清债模式把配额 10 → 15，**卡数从 30 涨到 45** | 反向 |
| 5 | 已会词出口 | 墨墨「熟知」= 永久不再复习 | **没有出口**，毕业了也继续按 30 天循环占配额 | 缺口 |
| 6 | 配额 | 动态学习量（按完成情况调） | 固定 10，不看用户实际完成能力 | 缺口 |
| 7 | 新词排序 | 按词书顺序 / 主题 / 频率 | `news.shuffled()` **纯随机**，场景被拆散 | 可优化 |
| 8 | 长间隔词忘后 | 缩回上一档再递增 | **一律打回 days=1** | 待商榷（见 §3 P1-1） |
| 9 | 遗忘史 | difficulty 每卡独立 | `lapses` ✓ 已有，并用于排序与抽权 ✓ | **已对齐** |
| 10 | 自主练习 | —— | R10 池型 + 加权随机 + 零写入 | **已对齐**（主流没有对应物） |

## 3. 优化建议

### P0-1 升级判据从「当日满 3」改为「首答即升级 + 当日只做巩固」★最重要

**现状机制**（`markKnown`）：`counts[id] + 1` → 只有 `count >= 3` 且 `lastSeen != today` 才写 `TermState`。而 `currentDay()` 在 `date != today()` 时把整个 `DayState` 作废。

**推导出的死锁**：

```
用户每天只能做完 5 张卡  →  每个词当天最多答对 1–2 次
                        →  counts 永远到不了 3
                        →  永远不写 TermState（词永远是「未学」或原到期状态）
                        →  明天队列一模一样，卡数不减
                        →  永远学不会任何词
```

词库 368 词、配额 10，而目标用户是老人、每天可能只有几分钟——**这个区间不是边缘情况，很可能是常态**。

**建议**（借墨墨规则 1）：把长期调度的决定权交给**当天第一次作答**——

- `markKnown` → 直接升级 `TermState`（等价于「连击目标 = 1」）；
- 同日该词**再出现时以浏览卡形态**（复用 R10 已有的 `CardMode.FREE`）巩固：不考、不写状态、不改队列；
- `DayState.counts` 降级为「该词今天是否已作答」的标记（或直接删掉）。

**收益**：

| 指标 | 现状 | 改后（模拟方案 B） |
|---|---|---|
| 每日卡数（f30=30%） | 39.6 张 | **13.1 张** |
| 能学到的词数 | 119 / 368 | **177 / 368** |
| 复习迟到量 | 15 | **9**（更健康） |
| 做不完的用户 | **永远学不会** | 每天推进 n 个词，进度跨天不丢 |

（数字出自 `learning-mechanism-review.md` §5／§8，模拟器可复跑。）

**与实证一致**：这等于把「同日密集重复 2 次」换成「跨天间隔提取」，正是 Maddox & Balota 说的「对老人有效的那种重复」。

**代价（必须一起接受）**：

1. 答错的纠错机会变少——一次误点 √ 就把词推出 1 天（首答间隔只有 1 天，风险有限），长间隔词的误点才贵 → **需要 P0-2 配套**。
2. 失去「当天三重确认」的仪式感。对老人这可能是有价值的正反馈 → 用「答对即播报『学会啦』+ 当天以浏览卡再见一次」补回。
3. **`DayState.counts` 的语义要重写**，属结构性变更 → 必须回 Phase 1。

---

### P0-2 配套：加一个纠错窗口（借扇贝的「更改为不认识」）

首答即升级之后，「误点」的代价被放大，纠错入口从「锦上添花」变成「必需品」。

建议：作答后卡片底部出现一个**短时可用的撤销入口**（例如 5 秒内有效，或滑动离开即失效），文案沿用老人能懂的话：「点错了？改一下」。撤销要一并回滚 `TermState` / `DayState` / 队列追加 —— 实现上最省事的做法是**在 UI 层缓存作答前的快照**，撤销时整体回写。

顺便解决现状下另一个反向误点：现在一次误点「忘了」会把 `days=30` 的词直接打回 1 天（`markForgot` 写 `{1, today, lapses+1}`），一次手滑抹掉 30 天进度。

---

### P0-3 队列内交错：新词不能再垫底

**现状**：`pool = (due + news).take(DAILY_POOL_QUOTA)` → 到期词**全部排在前**，新词只在到期词不足时补位。配合 R7 前向拦截（不能跳过），用户每天必须从头啃完复习才能见到新词。

**后果**：`due ≥ 5` 而用户只能做完前 5 张时，**新词永远排在第 6–10 位，永远轮不到**——第二天重建队列，新词又被挤到后面。对「做不完」的用户，新词通道等于关闭。

**建议**：把 `due + news` 改成**交错编排**，保证队列前 1/3 内至少有 1–2 个新词（例如每 3 张插 1 个新词，或新词固定占据第 2 位）。改动很小（只动 `buildQueue` 的合并顺序），但决定了「学不完的用户是否还有新词可学」。

主流对应：Anki 的新卡是独立的并发上限；墨墨的不设固定新学量但新学与复习同时存在。

---

### P0-4 清债日不应该更重

**现状**：`due >= DEBT_THRESHOLD(20)` → `due.take(DEBT_QUOTA(15))`。15 词 × 3 张 = **45 张**，比平常的 30–40 张还重，方向与「避免老人单日负担过重」相反。

**建议**：清债日**保持总卡数不变、只降低每词卡数**。如果 P0-1 落地（每词 1 张），这条自动消失：「清债日 15 词 × 1 张 = 15 张」，反而是一天里最轻的。

墨墨的对应规则：「今天复习量大的时候，新学的单词就少一点；复习量少的时候，新学就多一点」——**总量守恒**，而 Mando 现在是「债多则总量也涨」。

---

### P0-5 给「我早就会了」一个出口（借墨墨的「熟知」）

**现状**：一个词唯一的归宿是永远按 30 天循环（`INTERVALS.last()` 封顶、`nextInterval` 返回同值）。368 词里必然有一部分是老人本来就熟的（「电话」「医院」「吃饭」）。

**后果**：这些词每天都在 `due` 里占配额、每天要走一遍考核，把真正需要练的词挤出去。这是纯粹的浪费。

**建议**：给 `TermState` 加一个 `retired` 状态（或 `days = 0` 哨兵值），语义是「永久不再安排」。

**必须配一道闸门**，否则会退化成「老人自评背单词」——对可能有认知衰退的用户，自我评估偏乐观：

- 只对 `days >= 30`（已封顶）的词开放该入口；
- 或在达到 `days = 30` 后再连对 2 次才解锁按钮。

**收益**：直接释放配额。按 10% 的词是「本来就熟」估算（**量级示意，非实测**），约 37 个词退出循环，等效于把「学到词数上限」从 300 抬到 337，且学习期更早进入「全是真需要的词」。

---

### P1-1 长间隔词的「忘了」是否一定要归零？（**建议保留现状，但值得记录**）

现状 `markForgot` 一律写 `days=1`。两个实证方向**互相拉扯**：

- 支持归零：间隔提取的核心就是「出错后缩短间隔、立即复现」；
- 反对归零：Haslam 的做法是**缩回上一档**再重新递增——一次错误不该抹掉全部进度。一个 `days=30` 的词忘了就打回 1 天，等于把它和刚学会的新词放同一档。

**建议**：**暂不改**（归零对认知衰退风险人群更安全），但把这条记进设计文档的已知取舍。若真机数据显示 `f30` 很高（长间隔大量失败），再考虑改成「回退到上一档」。

---

### P1-2 `news` 按场景聚簇，不要纯洗牌

**现状**：`news = scope.filter { termStates[it] == null }.shuffled()` —— 纯随机。一天的 10 个新词可能横跨医院、交通、购物三个场景，互相不激活。

**建议**：先按 `scene` 分组，在组内洗牌，再决定先上哪个场景（同一天的新词尽量同场景，或按「场景轮转」逐日推进）。对老人的记忆，同一场景的词互相支撑远好于随机混合；而且和「场景分区」的自主练习天然呼应。

---

### P1-3 配额自适应（不看数据就会一直错配）

**现状**：`DAILY_POOL_QUOTA = 10` 恒定，不看用户实际完成能力。

**建议**：按近 7 天的**完成率**调：完成率 < 80% → 配额降 1（最低 5）；连续 7 天完成率 > 95% → 升 1（最高 15）。

这直接对应墨墨的「调整每日学习量就是在调整每天的学习压力」。对 Mando 还有一个额外好处：**配额成了 A/B 实验的天然变量**，能顺手拿到「用户到底能承受多少张卡」这个目前完全未知的数。

---

### P2 内容与反馈侧（低成本、可并行）

- **一词一图**（借百词斩）：现在的 `icon` 是场景 emoji，可以升级为该词的**实拍图**。老人对图像的记忆显著强于文字。
- **`tip` 用第一人称生活场景句**：不背单词靠真实语境，Mando 的 `tip` 已经是语境化的 ✓，可以再往「我明天要去医院复查」这类第一人称句子收，比解释更有锚定力。
- **完成卡之后给浏览流一点轻反馈**（R10 下期已记）：不写学习状态，只是让老人知道「今天又看了 20 个词」。
- **booster session**：长期保留靠后续加强——现有 `days=30` 封顶其实就是一种弱化的 booster，可考虑对「毕业很久的词」做一次低频抽查（例如 90 天一次）。

## 4. 明确**不建议**照搬的

| 主流做法 | 为什么 Mando 不该抄 |
|---|---|
| FSRS 的 21 权重 ML | 需要海量复习日志才能训练。Mando 连 `f30` 都还没拿到，模型只会过拟合。**搬概念（目标记忆率、每卡难度），别搬算法。** |
| 「模糊」四档反馈 | 二值 √/× 对老人是**刻意的简化**，加档位会提高每次决策成本 |
| 拼写 / 选择题测试 | 与「TTS 播报 + 大卡片」的交互模型冲突，也超出目标用户能力 |
| 「认识 / 不认识」前置自评 | 同上，且自评对认知衰退人群不可靠（见 P0-5 的闸门） |
| 连续签到 / streak / 惩罚机制 | 对老人是压力源而非激励；Mando 的完成卡已经提供了收尾仪式感 |
| 每日固定新学量 | 墨墨自己的帮助页就论证了它会导致复习量持续累加——Mando 的 `due` 优先 + `news` 补足方向是对的，只需修正 P0-3 的顺序问题 |

---

## 5. 建议的落地顺序

1. **先埋 `f30`**（仍然没做）。上面每一个数字都依赖它，P0-1 / P1-1 的取舍尤其依赖。现成数据就够：`days=30` 的词下次到期首答是 √ 还是 ×，按词累计。
2. **P0-1 + P0-2 一起做**（升级判据 + 纠错窗口）。单做 P0-1 会把误点风险暴露出来，两者是一对。这是唯一需要回 Phase 1 改状态机语义的改动。
3. **P0-3 交错** + **P0-4 清债日总量守恒**：纯 `buildQueue` 改动，风险低，可以和 P0-1 同批。
4. **P0-5 出口** + **P1-2 场景聚簇** + **P1-3 自适应配额**：独立、可增量。
5. `f30` 到手后**用模拟器重跑一遍**（`mechanism-sim.py`），再决定 P1-1 与封顶 30→60。
