# 学习复习调度优化 v5：清债调度与防泄题

## Goal

修复 v4 双层调度模型的两个结构性缺陷与一个交互漏洞，让 370 词量级的词库在长期使用中不会积累不可清偿的复习债务，且「考回忆」的复习交互不再被点按泄题破坏；同时修正完成卡的语义漏洞——不再把完成卡钉死在队尾，改为**整份当日队列真的处理完才出现**，并把 feed 改成**不允许越过未处理的卡**（未教读的新词卡 / 未作答的复习卡必须先处理，向前越界会被**静默**退回该卡，不播任何提示语；作答完则由 R8 等播报念完**自动前进**），使「滑到底」不再可能被当成完成。

## Requirements

### R1 消除到期债务堆积（P0）

- 现状：370 词全部到 15 天封顶后，稳态每日到期 ≈25 词 > 推荐频道配额 10，逾期队列只增不减。
- 要求：稳态每日到期量降到配额可覆盖的量级（目标 ≈12 词/天，配额 10 附近）。
- 手段：间隔阶梯延长为 1→3→7→15→30。

### R2「忘了」的词获得复习优先权（P0）

- 现状：markForgot 写 {days=1, lastSeen=今天}，次日该词 dueTime 是全部 due 词里最新的，在 buildQueue 的升序排序中排 due 池末尾；超额日 `take(10)` 首先挤掉的恰是昨天刚忘的词——与遗忘规律相反。
- 要求：有遗忘史（lapses）的词在 due 排序中优先于无遗忘史的词；同为无遗忘史时按到期日从旧到新。

### R3 高债务日动态扩配额（P0）

- 现状：固定配额 10，due 堆积时清偿速度不足，新词与复习债互相挤占。
- 要求：due ≥ 20 时推荐频道扩到 15 张全复习（不补新词）；否则维持「到期复核优先 + 新词补足共 10」。

### R4 分区毕业判定与封顶解耦（P0，随 R1）

- 要求：🎓 毕业门槛保持 days==15 不变（既有毕业分区无回归）；毕业词继续升到 30 天后毕业状态保持（不因超过门槛而回退）；「忘了」打回 1 仍即时退出毕业（可逆语义保持）。

### R5 复习卡防泄题 + 求助通道（P1）

- 现状：复习卡未作答时点卡片任意处触发 onSpeakTerm → TTS 直接念出「词 + 提示语」，先听再点「认识」连击照加，「考回忆」契约被一个 tap 打穿。
- 要求：
  - 考试态未作答时点卡片 → 只播「再想一想，想起来了吗？」，不念词、不念提示；
  - 新增「想看答案」求助按钮：展开拼音/提示但不写任何学习状态（连击、间隔、队列均不动），认识/忘了按钮保留，看完仍可作答走正常状态机；
  - 新学卡与已作答卡点按重听行为不变。

### R7 完成卡「真做完才出现」+ 不允许越过未处理的卡（P1）

- 现状：`pages` = 队列卡 + Done，完成卡无条件挂在队尾。只要手指够快，一张卡没答也能滑到底并听到「太棒了，今日任务完成！」。第一版补救（按未作答张数分流文案）补不住：口径只数「未作答复习卡」，而整天都是新词卡的场景下，新词卡被快速甩过时不会触发停稳教读、未作答复习卡数为 0，完成卡照样宣告完成——把完成卡钉死在队尾这件事本身就不该保留。
- 第二版补救（「滑过即回收队尾」）同样否决：回收是**不可见**的（屏幕上没有任何东西告诉用户可以划走，回收也不产生任何反馈），且**不终止**——回收无次数上限，而未答完时 FREE 页不追加（`doneIdx >= 0` 才追加），用户会陷入同一批卡的无限循环：没有完成卡、没有温故、没有任何解释。
- 要求：
  - **完成卡只在整个当日队列真的处理完时才存在**：未做完时 feed 里没有任何收尾页，队尾就是最后一张待处理的卡。
  - **待处理（pending）口径**：新学卡**当日未被教读**（未发生 `markSeen`）→ 待处理；复习卡未作答（`revealed[seq] != true`）→ 待处理；温故/自由刷（FREE）卡不计入。
  - **不允许越过未处理的卡**：向前停稳到某页时，若其前方仍存在待处理卡，则**退回最靠前的那一张**；`pages` 顺序**完全不动**（不回收、不重排、不写任何学习状态）。
  - **退回不播任何提示语**（静默退回）：这条规则是**结构性**的——滑不动就是滑不动，不需要用语音反复告知；而且用户随时可以翻回以前的卡，之后想往前走仍然要回来处理它，规则自己会说话。逐次拦截都播一句解释语对高龄用户是噪声。
  - **只拦前向，不拦回看**：下滑回看（含翻回之前任意一张已处理的卡）与完成卡之后的自由刷**不受限制**。**不得**使用 `userScrollEnabled = false`——它是全向开关，会把回看一起锁死，且卡片静止不动会被高龄用户误读为卡死。
  - **待处理卡的唯一出口**是 √ / ×（可先「👀 想看答案」再作答），作答完由 R8 自动前进；本版模型里**不存在「跳过 / 延后」这个动作**。
  - 完成卡文案回到**单一形态**（🎉 / 今日任务完成！/ 战果 / 继续上滑，随便看看）；「还有 N 张没作答」分支不再可达，一并删除。
  - **战果数字改为当日持久口径**：连击层的当日状态（`DayState`）增设当日「认识/忘了」次数计数，隔天随当日状态整体作废；完成卡与播报显示「今天学完了 N 个词 · 认识了 x 次，忘了 y 次」，重启不清零（N = 当日任务区去重词数）。
- **已评估的代价**（接受，见 design.md §5.4）：单日会话变成「逐张必须处理」，约 30 张卡 / 两三分钟；越界被拦时，用户为脱身而点「认识」的倾向上升——即放大 Out of Scope 里的「认识虚高」，列为监控项。

### R8 作答后自动前进（P1）

- 现状：作答后卡片停在原地，底部提示「上滑看下一个 ↑」，要用户自己上滑才能继续——高龄用户容易停在原地不知道下一步该做什么。
- 要求：
  - 在任意**可作答卡**（复习 REVIEW / 温故 FREE）上完成作答（√ 或 ×）后，**自动前进到下一张卡**（`pagerState.animateScrollToPage` 平滑动画）。
  - **必须等本次作答播报（词 + 提示 + 反馈）念完之后才翻页**：`TTSSpeaker.speak` 是 `QUEUE_FLUSH`，抢跑会把答案与反馈一起掐掉（与 R7 曾踩的坑同一根因）。实现为「最短停留兜底 + 等待朗读结束」。
  - **新词卡（NEW）不自动前进**：它是「看 / 听」卡，没有「作答完成」这个事件，节奏交给用户自己掌握（保留 `SwipeHint`）。
  - 用户若在播报期间自己滑动（前进或回看），**放弃本次自动前进**，不与用户抢方向。
  - 作答后未移除的考核卡追加在**队尾**，因此「下一张 = 当前下标 + 1」始终成立；若当前卡是最后一张待处理卡，自动前进恰好落在完成卡上（完成卡本身仍按 R7 条件出现）。
- 与 R7 的关系：R7 管「没作答不能走」，R8 管「作答完自动走」。两条合起来，feed 只剩一种前进方式——**处理完当前卡**。

### R6 兼容与迁移（约束）

- 旧持久化 JSON（无 lapses 字段）加载不崩、语义正确（lapses 缺省 0）。
- id 永不复用、SharedPreferences 单 key 存储结构不变。

## Out of Scope（本期明确不做）

- 三选一拼音客观校验（「认识」自评虚高问题）——留下期评估
- 场景频道软配额、跨午夜前台重载、同词考核卡间隔打散（P2 项）
- Room 迁移 / TermState 结构性重构
- ~~**未作答强制拦截 / 滑动锁定**（经评审否决：强制作答会把「跳过」转换成「乱答」，污染连击层与 lapses；而跳过不写状态、次日 dueTime 更旧自然前排，本身无债务风险。R7 改用「滑过即回收队尾」来保证前向可达，仍不锁滑动）~~ → **本轮改判**：原否决依据（跳过自愈、无债务）成立，但它只论证了「跳过不必记账」，没论证「跳过必须可用」；而兜底方案「滑过即回收」经代码核对后不可见且不终止（见 R7）。故改为**不允许越过未处理的卡**（**静默**退回该卡，只拦前向、不拦回看）。改判理由与代价见 design.md §5.2 / §5.4
- **显式的「跳过 / 稍后再说」动作**——本期不做。若将来要保留跳过能力，必须是**显式动作 + 明确代价**（如延到次日），不能是滑动的副作用（老人手抖误甩会误写库）
- ~~作答后自动翻页（完成卡出现时不自动前进）——保持「作答后用户自己上滑」的现有主流程~~ → **本轮改判**：R8 改为「作答后自动前进」，且**包含**落点恰好是完成卡的情形（那是当日会话的自然收尾）。原决策的思路是「把节奏交给用户」，但实测的代价是高龄用户答完停在原地、不知道下一步做什么。

## Acceptance Criteria

- [ ] INTERVALS = [1, 3, 7, 15, 30]；days==15 的词满 3 连击后播报「30 天后再来复习」
- [ ] GRADUATED_DAYS 固定为 15；isSceneGraduated 判定为 days >= 15（毕业词升 30 后🎓不消失）
- [ ] TermState 含 lapses：忘了 +1、升级时减半；持久化读写对称
- [ ] buildQueue 的 due 排序：lapses 降序优先，其次 dueTime 升序
- [ ] due ≥ 20 时推荐频道 pool = due.take(15)，无新词；due < 20 时行为与现状一致
- [ ] 旧 JSON（无 lapses）加载正常，lapses 默认 0
- [ ] 复习卡未作答：点卡片 TTS 只说「再想一想，想起来了吗？」
- [ ] 「想看答案」：展开拼音+提示；不写连击/间隔/队列状态；按钮保留可作答
- [ ] 新学卡、已作答卡点按重听行为不变
- [ ] 未做完时 feed 中不存在完成卡：滑到最后一张待处理卡后没有「今日任务完成」文案，也不出现含完成语义的播报
- [ ] 当日队列真的处理完（新词都教读过、复习词都满 3 连击移出）后，完成卡出现在队尾
- [ ] 站在未作答的复习卡上向前划：**静默**退回本卡（不播任何提示语）；`pages` 顺序不变、错位不发生、连击/间隔/answered 均未变化
- [ ] 快甩过一张未教读的新词卡：静默退回该卡；停稳教读（markSeen）后才算处理完毕、才可继续上滑
- [ ] 复习卡作答（√ / ×）后**自动前进**到下一张卡；且翻页发生在**作答播报念完之后**，答案与反馈不被掐断
- [ ] 完成最后一张待处理卡后自动前进，落在完成卡上
- [ ] 播报期间用户自己滑动（前进或回看）→ 放弃本次自动前进，不抢方向
- [ ] 新词卡不自动前进（仍需用户自己上滑）；温故（FREE）卡作答后同样自动前进
- [ ] 完成卡为单一形态：「🎉 / 今日任务完成！」+「今天学完了 N 个词 · 认识了 x 次，忘了 y 次」+「继续上滑，随便看看」+ SwipeHint
- [ ] 战果数字为当日持久口径：答后重启再进，数字不归零
- [ ] 温故（自由刷）卡不计入待处理数；完成卡之后仍可无限上滑，且**不被拦截**
- [ ] **向下滑回看不受限制**；未引入 `userScrollEnabled = false` 或任何全向锁定
- [ ] `gradlew assembleDebug` 编译通过
- [ ] prototype/index.html 交互契约同步（考试卡点按不泄读音 + 想看答案按钮 + 完成卡条件出现 + 向前越界退回且 DOM 顺序不变）
