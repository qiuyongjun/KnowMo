# 学习复习调度优化 v5：清债调度与防泄题

## Goal

修复 v4 双层调度模型的两个结构性缺陷与一个交互漏洞，让 370 词量级的词库在长期使用中不会积累不可清偿的复习债务，且「考回忆」的复习交互不再被点按泄题破坏；同时修正完成卡的语义漏洞——不再把完成卡钉死在队尾，改为**整份当日队列真的处理完才出现**，并把 feed 改成前向消化（滑过的未答卡回收队尾），使「一路往上滑就能做完」成立。

## Requirements

### R1 消除到期债务堆积（P0）

- 现状：370 词全部到 15 天封顶后，稳态每日到期 ≈25 词 > 推荐频道配额 10，逾期队列只增不减。
- 要求：稳态每日到期量降到配额可覆盖的量级（目标 ≈12 词/天，配额 10 附近）。
- 手段：间隔阶梯延长为 1→3→7→15→30。

### R2「忘了」的词获得复习优先权（P0）

- 现状：markForgot 写 {days=1, lastSeen=今天}，次日该词 dueTime 是全部 due 词里最新的，在 buildQueue 的升序排序中排 due 池末尾；超额日 `take(10)` 首先挤掉的恰是昨天刚忘的词——与遗忘规律相反。
- 要求：有遗忘史（lapses）的词在 due 排序中优先于无遗忘史的词；同为无遗忘史时按到期日从旧到新。

### R3 高债务日动态扩配额（P0）

- 现状：固定配额 10，due 堆积时清偿速度不足，新词与复习债互相挤占。
- 要求：due ≥ 20 时推荐频道扩到 15 张全复习（不补新词）；否则维持「到期复核优先 + 新词补足共 10」。

### R4 分区毕业判定与封顶解耦（P0，随 R1）

- 要求：🎓 毕业门槛保持 days==15 不变（既有毕业分区无回归）；毕业词继续升到 30 天后毕业状态保持（不因超过门槛而回退）；「忘了」打回 1 仍即时退出毕业（可逆语义保持）。

### R5 复习卡防泄题 + 求助通道（P1）

- 现状：复习卡未作答时点卡片任意处触发 onSpeakTerm → TTS 直接念出「词 + 提示语」，先听再点「认识」连击照加，「考回忆」契约被一个 tap 打穿。
- 要求：
  - 考试态未作答时点卡片 → 只播「再想一想，想起来了吗？」，不念词、不念提示；
  - 新增「想看答案」求助按钮：展开拼音/提示但不写任何学习状态（连击、间隔、队列均不动），认识/忘了按钮保留，看完仍可作答走正常状态机；
  - 新学卡与已作答卡点按重听行为不变。

### R7 完成卡「真做完才出现」+ feed 前向消化（P1）

- 现状：`pages` = 队列卡 + Done，完成卡无条件挂在队尾。只要手指够快，一张卡没答也能滑到底并听到「太棒了，今日任务完成！」。上一版（完成卡按未作答张数分流文案）补不住：口径只数「未作答复习卡」，而整天都是新词卡的场景下，新词卡被快速甩过时不会触发停稳教读、未作答复习卡数为 0，完成卡照样宣告完成——把完成卡钉死在队尾这件事本身就不该保留。
- 要求：
  - **完成卡只在整个当日队列真的处理完时才存在**：未做完时 feed 里没有任何收尾页，队尾就是最后一张待处理的卡。
  - **待处理（pending）口径**：新学卡**当日未被教读**（未发生 `markSeen`）→ 待处理；复习卡未作答（`revealed[seq] != true`）→ 待处理；温故/自由刷（FREE）卡不计入。
  - **前向消化**：用户向前滑过一张仍待处理的卡时，该卡被移到队尾（完成卡之前 / 队尾）。于是「身前永远是没答完的卡，身后永远是已处理的卡」，用户只需一路往上滑就能做完，不需要回看补答；滑过的卡也不会被丢弃——跳过等于「稍后」，不是「放弃」。
  - **滑动全程保持可用**：不因未作答而锁定滑动（决策理由见 design.md §1）。上一版靠「提示往回滑」来兜底，本版靠前向回收消除「必须回看」这个前提。
  - 完成卡文案回到**单一形态**（🎉 / 今日任务完成！/ 战果 / 继续上滑，随便看看）；「还有 N 张没作答」分支不再可达，一并删除。
  - **战果数字改为当日持久口径**：连击层的当日状态（`DayState`）增设当日「认识/忘了」次数计数，隔天随当日状态整体作废；完成卡与播报显示「今天学完了 N 个词 · 认识了 x 次，忘了 y 次」，重启不清零（N = 当日任务区去重词数）。

### R6 兼容与迁移（约束）

- 旧持久化 JSON（无 lapses 字段）加载不崩、语义正确（lapses 缺省 0）。
- id 永不复用、SharedPreferences 单 key 存储结构不变。

## Out of Scope（本期明确不做）

- 三选一拼音客观校验（「认识」自评虚高问题）——留下期评估
- 场景频道软配额、跨午夜前台重载、同词考核卡间隔打散（P2 项）
- Room 迁移 / TermState 结构性重构
- **未作答强制拦截 / 滑动锁定**（经评审否决：强制作答会把「跳过」转换成「乱答」，污染连击层与 lapses；而跳过不写状态、次日 dueTime 更旧自然前排，本身无债务风险。R7 改用「滑过即回收队尾」来保证前向可达，仍不锁滑动。理由见 design.md §5）
- 作答后自动翻页（完成卡出现时不自动前进）——保持「作答后用户自己上滑」的现有主流程

## Acceptance Criteria

- [ ] INTERVALS = [1, 3, 7, 15, 30]；days==15 的词满 3 连击后播报「30 天后再来复习」
- [ ] GRADUATED_DAYS 固定为 15；isSceneGraduated 判定为 days >= 15（毕业词升 30 后🎓不消失）
- [ ] TermState 含 lapses：忘了 +1、升级时减半；持久化读写对称
- [ ] buildQueue 的 due 排序：lapses 降序优先，其次 dueTime 升序
- [ ] due ≥ 20 时推荐频道 pool = due.take(15)，无新词；due < 20 时行为与现状一致
- [ ] 旧 JSON（无 lapses）加载正常，lapses 默认 0
- [ ] 复习卡未作答：点卡片 TTS 只说「再想一想，想起来了吗？」
- [ ] 「想看答案」：展开拼音+提示；不写连击/间隔/队列状态；按钮保留可作答
- [ ] 新学卡、已作答卡点按重听行为不变
- [ ] 未做完时 feed 中不存在完成卡：滑到最后一张待处理卡后没有「今日任务完成」文案，也不出现含完成语义的播报
- [ ] 当日队列真的处理完（新词都教读过、复习词都满 3 连击移出）后，完成卡出现在队尾
- [ ] 向前滑过一张仍未作答的复习卡：该卡移到队尾（完成卡之前）；不写任何学习状态（连击/间隔/answered 均不动）；当前显示页不错位
- [ ] 向前滑过一张尚未教读的新词卡：同样回收队尾；只有停稳被教读（markSeen）才算处理完毕
- [ ] 完成卡为单一形态：「🎉 / 今日任务完成！」+「今天学完了 N 个词 · 认识了 x 次，忘了 y 次」+「继续上滑，随便看看」+ SwipeHint
- [ ] 战果数字为当日持久口径：答后重启再进，数字不归零
- [ ] 温故（自由刷）卡不计入待处理数；完成卡之后仍可无限上滑
- [ ] 滑动始终可用（未引入滑动锁定；滑过的卡回收而非丢弃）
- [ ] `gradlew assembleDebug` 编译通过
- [ ] prototype/index.html 交互契约同步（考试卡点按不泄读音 + 想看答案按钮 + 完成卡条件出现 + 滑过即回收）
