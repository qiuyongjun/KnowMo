# 学习复习调度优化 v5：清债调度与防泄题

## Goal

修复 v4 双层调度模型的两个结构性缺陷与一个交互漏洞，让 370 词量级的词库在长期使用中不会积累不可清偿的复习债务，且「考回忆」的复习交互不再被点按泄题破坏；同时修正完成卡的语义漏洞——不再把完成卡钉死在队尾，改为**整份当日队列真的处理完才出现**，并把 feed 改成**不允许越过未处理的卡**（未教读的新词卡 / 未作答的复习卡必须先处理，向前越界会被**静默**退回该卡，不播任何提示语；作答完则由 R8 等播报念完**自动前进**），使「滑到底」不再可能被当成完成；并把**场景分区的定位改判**为**专题自主练习**（R9：不设完成卡、不做前向拦截、不做到期筛选、滑完停住），R7 的完成卡与前向拦截随之收敛到每日任务频道；并把**自主学习**（完成卡之后的温故流 + 场景分区）从「考试态」改判为**纯浏览的池型频道**（R10：无 √/× 作答、分区加权随机无限流、未学词只「看」不算学、新词入口唯一化到每日任务）；最后把调度内核的升级判据从「当日满 3 连击」改为「首答定调度」（R11：当日首答即写间隔层、作答后不再追加考核卡、新词交错编排、清债日随「每词一卡」自然守恒、附 f30 观测点），消除「做不完当日队列的用户永远学不会任何词」的死锁。

## Requirements

### R1 消除到期债务堆积（P0）

- 现状：370 词全部到 15 天封顶后，稳态每日到期 ≈25 词 > 推荐频道配额 10，逾期队列只增不减。
- 要求：稳态每日到期量降到配额可覆盖的量级（目标 ≈12 词/天，配额 10 附近）。
- 手段：间隔阶梯延长为 1→3→7→15→30。

### R2「忘了」的词获得复习优先权（P0）

- 现状：markForgot 写 {days=1, lastSeen=今天}，次日该词 dueTime 是全部 due 词里最新的，在 buildQueue 的升序排序中排 due 池末尾；超额日 `take(10)` 首先挤掉的恰是昨天刚忘的词——与遗忘规律相反。
- 要求：有遗忘史（lapses）的词在 due 排序中优先于无遗忘史的词；同为无遗忘史时按到期日从旧到新。

### R3 高债务日动态扩配额（P0）

- 现状：固定配额 10，due 堆积时清偿速度不足，新词与复习债互相挤占。
- 要求：due ≥ 20 时推荐频道扩到 15 张全复习（不补新词）；否则维持「到期复核优先 + 新词补足共 10」。

### R4 分区毕业判定与封顶解耦（P0，随 R1）

- 要求：🎓 毕业门槛保持 days==15 不变（既有毕业分区无回归）；毕业词继续升到 30 天后毕业状态保持（不因超过门槛而回退）；「忘了」打回 1 仍即时退出毕业（可逆语义保持）。

### R5 复习卡防泄题 + 求助通道（P1）

- 现状：复习卡未作答时点卡片任意处触发 onSpeakTerm → TTS 直接念出「词 + 提示语」，先听再点「认识」连击照加，「考回忆」契约被一个 tap 打穿。
- 要求：
  - 考试态未作答时点卡片 → 只播「再想一想，想起来了吗？」，不念词、不念提示；
  - 新增「想看答案」求助按钮：展开拼音/提示但不写任何学习状态（连击、间隔、队列均不动），认识/忘了按钮保留，看完仍可作答走正常状态机；
  - 新学卡与已作答卡点按重听行为不变。

### R7 完成卡「真做完才出现」+ 不允许越过未处理的卡（P1）

- 现状：`pages` = 队列卡 + Done，完成卡无条件挂在队尾。只要手指够快，一张卡没答也能滑到底并听到「太棒了，今日任务完成！」。第一版补救（按未作答张数分流文案）补不住：口径只数「未作答复习卡」，而整天都是新词卡的场景下，新词卡被快速甩过时不会触发停稳教读、未作答复习卡数为 0，完成卡照样宣告完成——把完成卡钉死在队尾这件事本身就不该保留。
- 第二版补救（「滑过即回收队尾」）同样否决：回收是**不可见**的（屏幕上没有任何东西告诉用户可以划走，回收也不产生任何反馈），且**不终止**——回收无次数上限，而未答完时 FREE 页不追加（`doneIdx >= 0` 才追加），用户会陷入同一批卡的无限循环：没有完成卡、没有温故、没有任何解释。
- 要求：
  - **完成卡只在整个当日队列真的处理完时才存在**（**仅每日任务频道**，分区见 R9）：未做完时 feed 里没有任何收尾页，队尾就是最后一张待处理的卡。
  - **待处理（pending）口径**：新学卡**当日未被教读**（未发生 `markSeen`）→ 待处理；复习卡未作答（`revealed[seq] != true`）→ 待处理；温故/自由刷（FREE）卡不计入。
  - **不允许越过未处理的卡**（**仅每日任务频道**；分区见 R9）：向前停稳到某页时，若其前方仍存在待处理卡，则**退回最靠前的那一张**；`pages` 顺序**完全不动**（不回收、不重排、不写任何学习状态）。
  - **退回不播任何提示语**（静默退回）：这条规则是**结构性**的——滑不动就是滑不动，不需要用语音反复告知；而且用户随时可以翻回以前的卡，之后想往前走仍然要回来处理它，规则自己会说话。逐次拦截都播一句解释语对高龄用户是噪声。
  - **只拦前向，不拦回看**：下滑回看（含翻回之前任意一张已处理的卡）与完成卡之后的自由刷**不受限制**。**不得**使用 `userScrollEnabled = false`——它是全向开关，会把回看一起锁死，且卡片静止不动会被高龄用户误读为卡死。
  - **待处理卡的唯一出口**是 √ / ×（可先「👀 想看答案」再作答），作答完由 R8 自动前进；本版模型里**不存在「跳过 / 延后」这个动作**。
  - 完成卡文案回到**单一形态**（🎉 / 今日任务完成！/ 战果 / 继续上滑，随便看看）；「还有 N 张没作答」分支不再可达，一并删除。
  - **战果数字改为当日持久口径**：连击层的当日状态（`DayState`）增设当日「认识/忘了」次数计数，隔天随当日状态整体作废；完成卡与播报显示「今天学完了 N 个词 · 认识了 x 次，忘了 y 次」，重启不清零（N = 当日任务区去重词数）。
- **已评估的代价**（接受，见 design.md §5.4）：单日会话变成「逐张必须处理」，约 30 张卡 / 两三分钟【R11 修订：每词一卡后单日 10–15 张，约一两分钟】；越界被拦时，用户为脱身而点「认识」的倾向上升——即放大 Out of Scope 里的「认识虚高」，列为监控项。

### R8 作答后自动前进（P1）

- 现状：作答后卡片停在原地，底部提示「上滑看下一个 ↑」，要用户自己上滑才能继续——高龄用户容易停在原地不知道下一步该做什么。
- 要求：
  - 在**复习卡（REVIEW）**上完成作答（√ 或 ×）后，**自动前进到下一张卡**（`pagerState.animateScrollToPage` 平滑动画）。**（R10 收窄）**温故流改为纯浏览卡（R10 D1）之后不再有作答事件，自动前进的作用域收敛到每日任务的复习卡——浏览卡**不**自动前进（用户还没看完就翻页是打扰）。
  - **必须等本次作答播报（词 + 提示 + 反馈）念完之后才翻页**：`TTSSpeaker.speak` 是 `QUEUE_FLUSH`，抢跑会把答案与反馈一起掐掉（与 R7 曾踩的坑同一根因）。实现为「最短停留兜底 + 等待朗读结束」。
  - **新词卡（NEW）不自动前进**：它是「看 / 听」卡，没有「作答完成」这个事件，节奏交给用户自己掌握（保留 `SwipeHint`）。
  - 用户若在播报期间自己滑动（前进或回看），**放弃本次自动前进**，不与用户抢方向。
  - 作答后未移除的考核卡追加在**队尾**，因此「下一张 = 当前下标 + 1」始终成立；若当前卡是最后一张待处理卡，自动前进恰好落在完成卡上（完成卡本身仍按 R7 条件出现）。
- 与 R7 的关系：R7 管「没作答不能走」，R8 管「作答完自动走」。两条合起来，feed 只剩一种前进方式——**处理完当前卡**。

### R9 场景分区 = 专题自主练习（P0）

- 现状：每个频道各自生成一套队列 + **一张完成卡**，文案一律「今日任务完成！」，一天最多能「完成」13 次；场景频道沿用 `due + news` 全量入队（每区约 30 词）。v5 R7 改判为「不允许越过未处理的卡」之后，分区变成**进区即约 120 张强制卡（15–20 分钟）**，且**没有任何收尾页能兜住它**——而 R7 想修的「滑到底 ≠ 完成」在分区里本就不该存在。
- 要求：**分区 = 专题自主练习**，与「每日任务」在语义上彻底分开：
  - **只有每日任务频道（`rec`）有完成卡**。分区 feed 里没有任何收尾页，也不播任何含完成语义的语音。
  - **R7 的前向拦截只在每日任务频道生效**。拦截的存在理由是「保证完成卡 = 真做完」（design §5.2），分区没有完成卡 → 该理由不成立 → 分区**自由划**（下滑回看本来就不受限）。
  - **分区不做到期筛选**：进分区就是该区**全部词**（已学词按「遗忘史降序 → 到期日升序」在前，未学词洗牌接后）。这同时排除了**空队列**：若按到期筛选，一个刚毕业的分区（全部词 days ≥ 15 且未到期）会在十几天里 pool 为空、`pageCount == 0` 白屏。
  - **滑完停住 + 轻提示**：分区队列处理到最后一张之后**不再追加任何页**；最后一张卡底部显示一句轻提示（「这个区就这些了 · 点上面的频道可以换区」）并并入该卡播报。它是**轻提示**不是完成卡——分区没有「完成」语义，禁止出现 🎉 / 「今日任务完成」类文案与播报。
  - **分区的断点 = 上次滑到的那一页**（不是「第一张待处理卡」）：分区自由划之后「在哪儿」≠「做到哪儿了」，回到分区应当落在离开时的位置。
  - **[R10 取代 → 分区不作答]** ~~分区作答仍走**同一套双层状态机**（连击层 + 间隔层，口径一致）：「忘了」⇒ days=1、lapses+1、连击清零；作答计入**当日战果**（全局当日口径，见 R7）。~~
- **本条的代价**（接受）：分区全量入队后，一个 30 词的区最多约 90 张卡。这不是「每日任务」而是可以随时进、随时走、想练多久练多久的练习区——正因为没有完成卡与前向拦截，「练不完」不会产生任何误导。

### R10 自主学习 = 纯浏览的池型频道（P0；修订 R8 与 R9 的温故/分区部分）

- 现状（R9 之后）：**温故流**（完成卡之后的自由刷）与**场景分区**都是**考试态**——先只出词、不出拼音，底部两个大按钮 √/×，点卡片只播「再想一想，想起来了吗？」（防泄题）；作答会**写间隔层**（随手 √ 可提前升级、随手 × 打回 days=1 并 lapses+1）并计入当日战果。分区还是一条**队列**（该区全部词、固定顺序、以「上次滑到的那一页」为断点、滑完停住 + 队尾轻提示）。
- 判断：**「自主学习」不该是第二个考试流**。用户的设想是「学完每日任务就能自主学习，没有限制，**也不需要让用户选择是否认识**，可以选分区也可以在推荐里由软件随机给词」。
- 要求：把两块自主学习入口**统一成同一个形态**——池型纯浏览频道，六个决定如下。

| # | 决策 | 内容 |
|---|---|---|
| D1 | 自主学习 = **纯浏览卡** | 温故流与分区都改成「词 + 逐字拼音 + 用途**全展开**、**没有 √/× 按钮**」的浏览卡：点卡片重听、点单字看讲解。**撤销**上一轮确认的「温故如果忘了，需要重新学习」，同时**解除** prd 里「不得把温故改成只读流」的回退禁令。 |
| D2 | 分区 = **无限流** | 滑到底继续按池追加（抽完重洗），想练多久练多久、随时切走。**撤销** R9 的「滑完停住 + 队尾轻提示」——无限流之后不存在「最后一张」，轻提示失去出现时机。 |
| D3 | 分区 = **该区全部词**（含未学词） | 确认 R9 现状：分区**不做到期筛选**（每区约 30 词，见 R9）。 |
| D4 | 分区里未学过的词**只「看」不算学会** | 浏览卡不作答 → 不写 `TermState` → 该词下次仍以**未学**身份出现。**新词入口唯一化到每日任务**：要学会必须回每日任务；分区不再 `markSeen`、也不再追加考核卡。 |
| D5 | 分区抽词 = **加权随机**（顺序不固定） | 权重**只读**既有状态算出：`w = 1 + 2×lapses + min(距上次学习天数, 60) / 30`；未学词取固定中等权重 `2.0`。抽完重洗。**只读参与权重、不写回任何状态**。 |
| D6 | 分区**不恢复位置** | 顺序随机之后页码没有意义：每次进分区都是一轮新的随机，从第一张开始。**撤销** R9 的「分区断点 = 上次滑到的那一页」。 |

- **保留下来的 R9 部分（不回归）**：分区**无完成卡**、**无前向拦截**、**不做到期筛选**（队列/池必非空 → 不白屏）、范围 = 该区全部词。
- **连锁结论（跑不掉，必须一起落）**：
  - **分区从「队列」变成「池」**：不再生成当日队列，`modes` / `answered` / `position` 对分区全部失去承载物；频道因此分成**队列型（仅 `rec`）**与**池型（分区）**两类（§design 5.7）。
  - **作答入口只剩复习卡**：温故与分区都没有作答 → `answer()` 只可能由每日任务的复习卡调用 → **R8 自动前进、防泄题话术自然收窄到复习卡**（`EXAM_TAP_HINT_SPEECH` 与「👀 想看答案」按钮只对复习卡可达）。
  - **战果口径自动收敛**：`knownAnswers` / `forgotAnswers` 只在 `answer()` 里 +1，而 `answer()` 只剩复习卡一条入口 → 完成卡的「认识了 x 次 / 忘了 y 次」**天然只统计每日任务频道**。这是描述修正，**不需要改计数代码**。
  - **温故流也一起变成浏览卡**：它与分区共用同一条池型追加逻辑（都是「从池里抽卡、无限追加」），差别只在池的构成（温故 = 推荐范围内已学词、等概率；分区 = 该区全部词、加权）。
- **本条已接受的代价**（用户 2026-09-18 明确接受）：
  1. **温故流与分区不再产生任何学习记录**。间隔层唯一的写入来源变成每日任务的复习卡作答；老人在分区里「看」再久，机制也认为什么都没发生——没有进度、没有战报，分区 🎓 毕业徽章也只能靠每日任务推进。「多练一会儿就能快点学完」这个指望落空。
  2. **学习效果全押在每日任务的 n 个词上**。温故与分区退化为消遣之后，间隔层每天的输入量就是 n（现在 10）——`research/learning-mechanism-review.md` 里那组杠杆（连击目标 / 新词保底 / 封顶 / 配额）从「可选优化」变成**唯一的调节手段**；而 n 的隐式上限 ≈ 30n（见 Out of Scope）会直接决定词库走得完还是走不完。



### R11 调度核心修订：首答定调度 + 新词交错 + f30 观测（P0；修订 v4「连击满 3」口径）

- 现状（R10 之后）仍存两个结构性缺陷（论证见 `research/learning-optimization-proposals.md`，数字见 `learning-mechanism-review.md` §5 方案 B）：
  1. **死锁**：「满 3 连击才升级」+「`DayState` 隔天整体作废」⇒ 做不完当日队列的用户（配额 10、老人每天可能只有几分钟——**大概率是常态而非边缘**）每天每词最多答 1–2 次 → counts 永远到不了 3 → `TermState` 永不写 → 队列每天一模一样、卡数不减 → **永远学不会任何词**。
  2. **新词垫底**：`(due + news).take(10)` 让到期词全在前，配合 R7 前向拦截 → `due ≥ 5` 而用户只做前 5 张时新词永远轮不到，次日重建又被挤后——做不完的用户新词通道等于关闭。
- 要求（2026-09-19 用户确认；**P0-2 撤销窗口明确不做**，见 Out of Scope）：
  - **R11-1 首答定调度（连击目标 3 → 1）**：复习/考核卡**当日首次作答**即写间隔层，并把该词**当日移除**：
    - 认识 → 无 `TermState` 首写 `{1, 今天, 0}`；有状态且 `lastSeen ≠ 今天` → `nextInterval` + `lapses` 减半；`lastSeen == 今天` → 闸门兜底不升级（正常流程同日无第二张考核卡，仅旧数据迁移日可达）。**「每日最多升一级」闸门保留**。
    - 忘了 → `{1, 今天, lapses+1}`；**当日同样移除**（不追加、当天不复现），次日因 lapses 降序排 due 前部优先回池。
    - **作答后不再追加任何考核卡**——同日第 2/3 次连击考核取消。模拟（f30=0.30）：日均卡数 39.6 → **13.1**、能学词 119 → **177**、复习迟到 15 → 9。
    - 新词卡流程不变：停稳教读（`markSeen`）→ 仍追加**恰好一张**考核卡；教读不算作答、不写 `TermState`（「学会」必须经过一次提取测试，新词入口唯一化不动）。
    - `DayState.counts` 语义降级为**当日已作答标记**（√/× 都写 1）；`DAILY_COMBO_TARGET` 常量删除。
  - **R11-2 新词交错编排**：`buildQueue` 的 pool 合并由 `(due + news).take(10)` 改为**交错**——格号 % 3 == 1 的位置优先放新词（news 空则放 due），其余位置优先 due（due 空则 news），直到配额或两池用尽。保证 news 非空时**队列前 3 张内必有新词**；news=0 时行为与现状一致。清债模式（due ≥ 20）仍不补新词。
  - **R11-3 清债日总量守恒（随 R11-1 自动达成，无代码改动）**：每词当日 1 张考核卡后，清债日 = 15 词 × 1 张 = **15 张**，不再出现 45 张的债日高峰；`DEBT_THRESHOLD` / `DEBT_QUOTA` 常量不动。
  - **R11-4 f30 观测点（只读、不改任何调度行为）**：作答时若该词**答前** `days == 30`，累计 `f30_total`（忘了再累计 `f30_fail`），落 SharedPreferences **独立 key**（不进主 state JSON）。后续调度决策（封顶 30→60、长间隔忘后是否回退上一档等）以此为输入。
- 代价（用户 2026-09-19 已知悉并接受）：
  1. **误点 √ 无撤销**（P0-2 被拒）：首答写库的最短间隔只有 1 天，误点代价有限；长间隔词误点代价大，由「每日最多升一级」闸门限制放大倍数。不引入任何撤销 UI。
  2. **「忘了」当天不复现**：错误纠正由作答播报整句（词 + 提示 + 反馈）承担；跨天再提取与「间隔提取对老人有效、密集提取只对年轻人有效」（Maddox & Balota 2015）一致。
  3. **失去「当天三重确认」仪式感**：由播报改「这个词学会啦！X 天后再来复习」补正反馈。

- 旧持久化 JSON（无 lapses 字段）加载不崩、语义正确（lapses 缺省 0）。
- id 永不复用；主状态仍单 key 存储（R11-4 的 f30 观测计数用独立 key，与学习状态解耦）。
